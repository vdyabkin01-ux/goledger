# GoLedger — правила для агента

## О проекте
Учебный финтех-проект: API кошелька на Go + много автотестов (unit, интеграционные, API, fuzz, нагрузка, мобильные).
Цель — портфолио QA/AQA и практика работы с ИИ-агентами.

## С кем работаешь
Влад — QA-инженер, Go только изучает. Поэтому:
- общайся по-русски, простым языком, термины поясняй;
- **не спеши**: один шаг — одна новая идея; следующий шаг только когда Влад сказал, что понял предыдущий;
- говори прямо и жёстко: если Влад предлагает херню — так и скажи, мат можно;
- попутно объясняй, как устроена работа с агентом: скиллы, хуки, субагенты, память, MCP — на примерах из этого проекта.

## Как делим работу: режим «Влад пишет сам»
- **Каждый файл проекта Влад создаёт и набирает руками.** Агент не пишет код проекта в файлы, если Влад прямо об этом не попросил.
- Шаг выглядит так: агент объясняет, что и зачем делаем → даёт маленький кусок кода и объясняет каждую строку → Влад набирает руками (без копипасты) → угадывает результат → запускает → объясняет своими словами, что сделал.
- Агент читает файлы Влада, проверяет, разбирает ошибки компилятора, отвечает на любые вопросы.
- Первая версия кода, написанная агентом (этапы 1–2), лежит в ветке `archive/agent-version` — это шпаргалка, а не основа.

## Как работаем с git
- В `main` напрямую не коммитим. Каждая задача — своя ветка (`feat/...`, `fix/...`, `test/...`, `chore/...`) и Pull Request.
- Сообщения коммитов — Conventional Commits на английском: `feat: add transfers endpoint`.
- Мёржит PR только Влад, после того как посмотрел дифф.

## Правила кода
- Деньги — только целые числа в минимальных единицах (`int64`, копейки/центы). Никаких `float`.
- Каждая новая фича приходит вместе с тестами.
- Секреты (пароли, ключи, токены) — только через переменные окружения, в git не попадают.
- Перед коммитом: `gofmt` и `go test ./...` должны проходить.
